# 每日签到 App（Pake 风格 · 多站 WebView）

一个 Android App，把多个需要每天签到的网站装进一个 App。
每个网站一个 WebView 入口，登录一次后 Cookie 保留在手机里，
每天在你设定的时间自动去签到，失败重试、失败了通知你手动点一下，所有结果都有记录。
每个站可以单独配代理（HTTP / SOCKS5），不需要代理的站照常直连。

## 功能对照你的需求

| 需求 | 实现 |
|---|---|
| 添加网站 | 首页右下角 +，填名字 + 网址 + 签到页地址 |
| 编辑网站 | 每个网站卡片上的“编辑”，打开后回填已有配置，改代理、改签到页、改按钮文字都行，保存后登录状态还在，不用重新登录 |
| 删除网站 | 卡片上的“删除”，同时清掉该站 Cookie 和记录 |
| 独立登录状态 | 见下文“Cookie 隔离” |
| 自动签到 | 打开签到页后注入 JS，按配置的按钮文字/选择器自动点签到 |
| 定时签到 | WorkManager，每天在首页设定的时间跑（默认 8:00），只在有网时跑，改时间立即重新排 |
| 代理 | 每个站单独配：直连 / HTTP / SOCKS5，填地址、端口、账号密码（可选），见下文“代理” |
| 失败重试 | 后台 HTTP 方式：失败 15 分钟后重试，最多 3 次；指数退避 |
| 签到记录 | 首页每个网站下显示最近一次结果；“记录”页按天看成功/失败 |
| 手动签到 | 点网站卡片上的“签到”或“打开”，进 WebView 手动点；自动失败时点通知也能直接打开 |
| 返回首页 | WebView 页顶部和底部都有“← 返回首页”大按钮，签到出结果后页面上方还会再出现一个，手机系统返回键也能回首页，不用退出 App 再进来 |
| 屏蔽广告 | 每个站单独开关：添加/编辑网站时有个“屏蔽广告”开关，打开网站后页面上方也有同一个开关，改完立即刷新生效。开：拦已知广告域名请求、藏广告位；关：广告原样显示。有的站屏蔽后按钮不见了，关掉再刷新就好 |

## Cloudflare 验证小页面打不开？

有的站（比如 bot-hosting.net 点续期）会用 `window.open` 弹一个带
Cloudflare 盾的小页面。旧版没接 WebView 的多窗口回调，所以小页面
根本不出现。新版已经接了：小页面会全屏显示出来，在里面完成验证，
点“关闭，回到主页面”后主页面刷新一次就能接着续期。
如果小页面还是空白，先把这个站的“屏蔽广告”关掉再试一次，
个别验证脚本会被广告规则误拦。

## 登录名和密码记不记得住？

先说结论：**密码本身 App 不存，登录状态靠 Cookie 记。**

WebView 不像 Chrome 那样有密码管理器，App 也不会把你的账号密码
存下来。登录一次后，网站发来的 Cookie 存在手机 WebView 里，
第二天打开一般还处在登录状态，不用重新输密码——前提是这个站的
登录有效期够长。明天看一眼就知道了：还登录着，说明 Cookie 有效；
如果又跳回登录页，说明这个站的会话过期了（有的站只有几个小时），
那就重新登录一次，或者登录时勾上网站自己的“记住我 / 保持登录”。

后台定时签到用的也是这份 Cookie：如果 Cookie 过期了，后台会记
“未登录：请先在 App 里打开该站登录一次”，你手动登录一次就好。

如果某个站还是记不住（比如 hax.co.id）：这个站没有账号密码框，
登录只有一个“Log in with Telegram”按钮，点开是 Telegram 的登录
小页面（oauth.telegram.org 的 iframe + 弹窗）。所以它记不住，
问题不在密码，在 Telegram 这一步：第三方 Cookie 关了、弹窗出不来、
广告规则拦了 telegram.org，都会让它每次都要重新登。
新版已经针对它改了三处：开了第三方 Cookie、接了弹窗、广告屏蔽
永不拦 telegram.org / Google / Facebook 登录。试法：先把 hax 这个
站的“屏蔽广告”关掉，重新点“Log in with Telegram”，在弹出的小页面
里完成 Telegram 确认，回到主页面后是登录状态就对了，第二天再看。
如果第二天还是掉登录，说明这个站自己的会话有效期就是一天不到，
那只能每天手动登一次，后台定时签到也登不进去。

## Cookie 隔离：先说实话

不同域名的网站，Android 的 `CookieManager` 本来就是按域名隔离的，
`a.com` 的 Cookie 不会发给 `b.com`，所以**不同网站之间天然独立**，
登录 A 不会顶掉 B，这部分不用额外处理。

真正需要隔离的只有一种情况：**同一个域名要登两个号**。
WebView 没有官方多 Profile，做法是：

1. 本项目默认：同一域名只保留一个号（最常见的情况，够用）；
2. 真要双号：把第二个号做成另一个 App 分身（改 `applicationId` 再装一个），
   或告诉我，我再给你加“独立进程 WebViewActivity”（每个站点一个
   `android:process`，代码量会翻倍，且后台定时会更不稳）。

## 自动签到的两条路（重要）

Android 后台跑 WebView 不可靠：系统会杀后台、WebView 要界面线程、
Cloudflare 这类验证在后台也过不了。所以分两层：

## 签到时间：自己定，不固定 8 点

首页顶部显示“每天签到时间：08:00”，点“更改时间”选几点几分，
保存后立即重新排定时任务，第二天就按新时间跑。
时间存在手机本地 `SharedPreferences`，不是写死在代码里的；
后台任务跑完也会按这个保存的时间排明天的。

注意：Android 省电会推迟后台任务。想准时跑，给 App 开“忽略电池优化”，
并允许通知；如果某天时间过了还没跑，看记录页有没有“网络异常”或失败记录。

## 代理：每个站单独配

在“添加网站”表单最下面填，留空就是直连：

- **类型**：直连 / HTTP / SOCKS5
- **地址 + 端口**：如 `127.0.0.1:7890`（Clash / sing-box 这类本地代理就填这个）、
  或远程代理的地址端口
- **账号密码**：代理没账号就空着；有账号就填，WebView 和后台都会用

限制（Android 本身的，不是 App 偷懒）：

1. **WebView 只支持 HTTP 代理。** SOCKS5 的站，前台打开可能直接打不开，
   但后台 HTTP 签到会走 SOCKS5。想前台也走 SOCKS5，请在手机上开系统 VPN /
   Clash 全局代理，或把 SOCKS5 转成 HTTP 代理再填进来。
2. **WebView 的代理是 App 全局的。** 打开走代理的 A 站，再打开直连的 B 站时，
   App 会先切代理再加载页面，不要同时开两个站。
3. **代理账号密码存在本地数据库里**，只在你自己手机上，不要把数据库文件发给别人。
   如果代理是你自己的 Clash 本地端口（127.0.0.1），一般没有账号密码，最省事。

测试方法：先加一个站，代理填好，点“打开/登录”——能打开登录页就说明
前台代理通了；再点“签到”，记录页显示成功就说明后台代理也通了。
如果前台能开、后台失败，大概率是该站的签到依赖 JS，只能走前台，见上文两条路。

### 用 NekoBox 的特别说明

NekoBox 本身就是代理服务器，签到 App 里填的 `127.0.0.1:2080`
只是指向它，NekoBox 必须先启动才有用：

1. NekoBox 里选好节点（先用能通的 VLESS），点底部小飞机启动，
   状态栏出现运行通知才算启动成功。
2. 默认不用改设置：入站设置里的混合端口默认就是 `2080`，
   如果你以前改过，就按改过的端口填进签到 App。
3. 签到 App 里编辑网站：类型 HTTP，地址 `127.0.0.1`，端口 `2080`。
4. 定时签到也一样：到设定时间时 NekoBox 必须正在运行，
   否则后台会报网络异常、重试 3 次后发通知让你手动处理。
   所以别在睡前把 NekoBox 划掉，给它开后台运行 / 忽略电池优化，
   或者开系统的“始终开启 VPN”。

### 用 v2rayNG 也一样，只是端口不同

v2rayNG 默认在本机开两个入口：SOCKS 是 `127.0.0.1:10808`，
HTTP 是 `127.0.0.1:10809`。签到 App 只认 HTTP，所以填：

- 类型：HTTP，地址 `127.0.0.1`，端口 **`10809`**（不是 10808，也不是 NekoBox 的 2080）

同样要先在 v2rayNG 里选好节点、点连接启动，到设定时间它必须正在运行。
如果改过端口，就按设置页里显示的实际 HTTP 端口填。

**A. 前台自动（最稳，推荐日常用）**
到设定时间发通知 → 你点一下（或 App 在前台时自动跑）→
依次打开每个站的签到页 → JS 自动找按钮点签到 → 记结果。
Cloudflare / 滑块验证的站只能走这条路，验证要人过一次。

**B. 后台 HTTP（能全自动的站才走这条路）**
登录时把该站 Cookie 存下来（`CookieManager.getCookie(url)` 存 Room），
定时任务用 OkHttp + 该站专属 CookieJar 直接请求签到接口。
前提是这个站的签到就是一个 GET/POST 请求，不依赖 JS。
`CheckinWorker` 里已经写好了这个逻辑，失败会重试。

所以每个站要配 3 样东西（在“添加/编辑网站”里填）：
1. `签到页 URL`：如 `https://panel.freecloud.ltd/checkin`
2. `按钮定位`：优先填按钮文字，如 `签到` / `Check In` / `每日签到`；
   文字找不到再填 CSS 选择器，如 `#checkin-btn`、`.btn-checkin`
3. `成功关键词`：签到成功后页面会出现什么字，如 `已签到` / `签到成功` / `Success`；
   用来判断这次到底成没成，而不是“点了就当成了”。

> 你之前那个 `panel.freecloud.ltd` 我记得：它有 Cloudflare 验证，
> 你自己在手机上都过不了验证。这种站后台 HTTP 一定失败，
> 只能前台 WebView、你先手动过验证登录好，再让 App 每天去点签到。
> 如果哪天它换了验证方式，再改成 B 路。

## 打包方法：传到 GitHub，Actions 自动编出 APK（推荐，你平时就这么干）

我这台机器没有 JDK / Android SDK，编不出 APK，所以项目里已经加好了
`.github/workflows/build-apk.yml`，推到 GitHub 就自动编译：

1. 在 GitHub 新建一个仓库（Private 私有就行，不用公开）
2. 把 `checkin-app` 里的全部文件传上去（包括隐藏的 `.github/` 文件夹，
   别只传 `app/`；用网页 Upload files 或 `git push` 都行）
3. 打开仓库的 **Actions** 标签页，等 `Build APK` 跑完变绿
   （第一次跑要下载 JDK / SDK / 依赖，大概要几分钟）
4. 点进那次运行，拉到最下面 **Artifacts**，下载 `checkin-app-debug`
   （是个 zip，解压后里面就是 `app-debug.apk`）
5. 把 APK 传到手机上安装。手机要允许“安装未知来源应用”，
   装完先在真机上测（模拟器测签到意义不大，很多站会拦模拟器 / 数据中心 IP）

改代码后想重新打包：改完再推一次 GitHub，Actions 会重新跑，
再去 Artifacts 下载新 APK 覆盖安装就行，不用卸载重装。

如果 Actions 红了：点进失败的那一步，看最后几十行报错发给我，
常见的是依赖下载超时，重跑一次（Run workflow / Re-run jobs）就好。

已知已修过的一个坑（2026-11-23）：`android-actions/setup-android@v3`
那一步会报 `Failed to find package 'tools'`、exit code 1。
那不是你的代码错了，是那个 Action 去装一个早已下架的 `tools` 包，
在 Gradle 开始编译之前就失败了。现在的工作流已经删掉了这一步，
直接用 GitHub 自带的 Android SDK。如果你看到的还是旧版工作流，
重新下载最新 zip 再传一次就行。

### 备选：本地 Android Studio 编译

电脑装 Android Studio（最新版即可，JDK 自带），把 `checkin-app` 打开，
等 Gradle 同步完 → 点 ▶️ Run 装到真机；要发给别人装：
菜单 Build → Generate App Bundles / APKs → Build APK(s)。

最低 Android 8.0（API 26），目标 Android 14（API 34）。
首次打开要给“通知”和“后台运行 / 忽略电池优化”权限，否则定时会被系统推迟。

## 文件结构

```
app/src/main/
  AndroidManifest.xml          权限 + WorkManager + 前台通知
  java/com/checkin/app/
    MainActivity.kt            首页列表、添加/删除、签到时间设置、手动签到入口
    data/Models.kt             Site（网站配置，含代理）/ CheckinLog（记录）/ Room 数据库
    web/AutoCheckinJs.kt       自动点签到按钮的 JS + 成功判断
    web/ProxyHelper.kt         代理：WebView（HTTP）+ OkHttp（HTTP/SOCKS5）
    worker/CheckinWorker.kt    每天定时（时间可设）、HTTP 签到（走各站代理）、失败重试、通知
    ui/Screens.kt              添加网站表单、记录页、WebView 登录页
```
